# Code of Conduct

## Our Commitment

SynthOps is an open-source project designed to support learning, analytics engineering, business intelligence, AI prototyping and decision-intelligence use cases through safe synthetic operational data.

We are committed to creating a respectful, inclusive and constructive environment for contributors, users and maintainers.

Everyone participating in this project is expected to engage professionally, respectfully and in good faith.

---

## Project Values

SynthOps is guided by the following values:

- respectful collaboration
- responsible data practice
- clear communication
- constructive feedback
- technical learning
- maintainable engineering
- transparent assumptions
- inclusive participation
- open-source usefulness

The goal is to build a project that others can understand, use, trust and contribute to.

---

## Expected Behaviour

Examples of positive behaviour include:

- using welcoming and respectful language
- giving constructive feedback
- being open to different perspectives
- explaining technical suggestions clearly
- documenting assumptions and limitations
- helping improve project quality
- respecting contributor time and effort
- raising concerns professionally
- focusing critique on ideas, code and documentation rather than individuals

---

## Unacceptable Behaviour

Unacceptable behaviour includes:

- harassment, intimidation or personal attacks
- discriminatory language or behaviour
- sexualised language or imagery
- insults, trolling or deliberately disruptive comments
- public or private harassment
- publishing another person's private information without consent
- misrepresenting synthetic data as real data
- contributing real sensitive data to the project
- encouraging unsafe or misleading use of generated data
- dismissive or hostile responses to good-faith questions

---

## Responsible Data Behaviour

Because SynthOps deals with synthetic data for potentially sensitive operational domains, contributors must follow responsible data principles.

Contributors must not add:

- real resident, patient, staff or provider records
- real clinical, safeguarding, financial or employment records
- real identifiers such as NHS numbers, national insurance numbers or financial account numbers
- real confidential organisational data
- sample data copied from private systems
- generated data presented as real-world evidence

Generated data should always be clearly described as fictional.

Synthetic assumptions should be documented and should not be presented as official benchmarks.

---

## Scope

This Code of Conduct applies to all project spaces, including:

- GitHub issues
- pull requests
- discussions
- documentation
- examples
- code review
- public project conversations
- community channels associated with the project

It also applies when someone is representing the project in public spaces.

---

## Reporting Concerns

If you experience or witness unacceptable behaviour, please report it to the project maintainer.

You may report concerns by:

1. contacting the maintainer through the contact method listed on their GitHub profile, or
2. opening a GitHub issue if the concern is non-sensitive and appropriate for public discussion.

Please include:

- what happened
- where it happened
- when it happened
- who was involved, if relevant
- any supporting context

Reports will be reviewed as fairly and respectfully as possible.

---

## Enforcement

The project maintainer may take appropriate action in response to unacceptable behaviour.

Actions may include:

- clarification of expectations
- editing or removing inappropriate content
- closing issues or pull requests
- limiting participation
- blocking users from the repository
- reporting serious abuse to the relevant platform

The response will depend on the severity and context of the behaviour.

---

## Good-Faith Learning

SynthOps is also intended to support learning.

Questions, mistakes and requests for clarification are welcome when made in good faith.

Contributors should feel able to ask:

- why a design decision was made
- how a generator works
- what a test is checking
- whether an assumption is realistic
- how to improve documentation or usability

The project should encourage learning while maintaining professional standards.

---

## Summary

SynthOps aims to be a respectful, responsible and professionally maintained open-source project.

Participants are expected to communicate constructively, protect responsible data principles and help create a project that is useful, trustworthy and welcoming to others.
